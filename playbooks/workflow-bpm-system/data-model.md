# Workflow / BPM Data Model (Architecture View)

## Core Aggregate Groups

## Core Domain Objects

- `ProcessDefinition`: logical process identity and metadata.
- `ProcessVersion`: immutable deployed process graph and execution semantics.
- `WorkflowInstance`: runtime process execution state.
- `TaskInstance`: human or system work item generated by workflow progression.
- `SignalMessage`: inbound or internal signal that advances process state.
- `TimerEvent`: scheduled trigger for reminder, timeout, or escalation behavior.
- `CompensationRecord`: state and result of compensating actions.

Purpose:
- Encapsulates process design-time and run-time entities.

## Metadata and Classification

- `ProcessVariableSchema`: typed variable definitions for process context.
- `ProcessVariableValue`: current variable values by instance scope.
- `DecisionInputSnapshot`: captured inputs to policy and decision evaluation.
- `DecisionOutcome`: resolved branching result and rationale.

Purpose:
- Supports policy-aware branching and replay-safe process interpretation.

## Access and Governance

- `RoleAssignment`: permissions for model authoring, operations, and approvals.
- `TaskAssignment`: ownership and delegation lineage for task execution.
- `OverrideAction`: authorized manual interventions and reasons.
- `AuditEvent`: immutable process, task, and administrative event history.

Purpose:
- Governs trust boundaries and accountability for process control.

## Process and Workflow Control

- `TransitionRecord`: explicit state transition and transition reason data.
- `ApprovalDecision`: human decision outcomes and rationale.
- `EscalationEvent`: policy-triggered escalation actions.
- `RetryAttempt`: execution retry history for failed side effects.
- `DeadLetterRecord`: failed processing records requiring operator action.

Purpose:
- Tracks execution control, exception handling, and recovery paths.

## Interchange and Integrations

- `IntegrationTask`: external side-effect request and outcome state.
- `OutboundEvent`: emitted process events for downstream systems.
- `ImportJob`: process definition or instance data import records.
- `ExportJob`: process telemetry and history export records.
- `IdempotencyKeyRecord`: deduplication and replay protection records.

Purpose:
- Governs reliable integration and data exchange boundaries.

## Key Relationships

- One `ProcessDefinition` has many `ProcessVersion` records.
- One `ProcessVersion` has many `WorkflowInstance` records.
- One `WorkflowInstance` has many `TaskInstance`, `TimerEvent`, and `TransitionRecord` records.
- `DecisionOutcome` references a `DecisionInputSnapshot` and the related process transition.
- `ApprovalDecision`, `EscalationEvent`, and `RetryAttempt` reference one workflow instance.
- `AuditEvent` correlates process, task, override, and integration actions.

## Invariants

- Each workflow instance references exactly one deployed process version.
- State transitions must follow the declared process graph.
- Task actions require valid assignment and authorization context.
- Timer events are uniquely keyed per workflow state and purpose.
- Compensation actions are idempotent and replay-safe.
- Audit records are immutable and append-only.
- External side effects are executed through idempotent integration paths.

## State Authority

- Authoritative domain state typically lives in ProcessDefinition, ProcessVersion, WorkflowInstance, TaskInstance, TransitionRecord, TimerEvent, DecisionOutcome, and ApprovalDecision.
- Supporting authoritative records commonly include RoleAssignment, TaskAssignment, OverrideAction, RetryAttempt, DeadLetterRecord, and integration checkpoint records within their own concerns.
- Derived or rebuildable forms often include operations dashboards, backlog summaries, search documents, notification delivery views, SLA aggregates, and reporting projections.
- Artifact or document references may be authoritative for linked files within their own boundary, but they typically do not own workflow execution truth.
- Keeping projection rebuild mechanisms explicit supports replay, recovery, and clearer separation between canonical execution state and operational views.
